## Phase 1: Authentication (plan section 3)

What changed:
- `app/auth.py`: `verify_firebase_token` uses `google.oauth2.id_token.verify_firebase_token` (signature against the securetoken certs, cached through a CacheControl session; `aud`, `exp`, `iat`), and also checks `iss`, a non-empty `sub` and `auth_time`. Email-link users (`sign_in_provider == "password"`) must have `email_verified == true`. It provides the dependencies `get_current_user` (401), `get_optional_user` (None without a header, 401 with a bad one) and `get_admin_user` (403 unless the verified email is in `ADMIN_EMAILS`).
- `app/main.py`: `resolve_user_id`, `verify_google_id_token`, `verify_developer_auth`, `X-User-Id`, `X-Dev-Key`, `/api/auth/verify` and the hard-coded admin emails are gone. There are 34 user endpoints, 15 admin endpoints (`/api/admin/*`, `/api/dev/*`, `/api/jobs/*`, submission approve/reject/reverse/takedown, `/api/heat/record`) and 4 optional-auth endpoints (route, options, options stream, edge info). `GET /api/saved-routes/{id}` used to return any user's route (`user_id=None`); it's now scoped to the owner. The GET stream endpoint is anonymous because EventSource can't send headers.
- CORS: only `CORS_ORIGINS` (default: the Pi Funnel origin and `http://localhost:5173`), no credentials, with `Authorization` and `Content-Type` headers allowed.
- `app/config.py`: `LOAM_ENV`, `FIREBASE_PROJECT_ID` (default `thepfisters`), `ADMIN_EMAILS`, `CORS_ORIGINS`; `DEVELOPER_ADMIN_EMAIL`/`DEVELOPER_ADMIN_KEY` deleted. In production, startup is refused if `CONNECTOR_SECRET_KEY` is still the in-code default.
- Migrations: `db/migrations/*.sql` plus `python -m scripts.migrate` (tracked in `schema_migrations`). `001_round7_auth.sql` adds `users.auth_provider`.
- Account migration (3.3): `app/account_migration.py`. On a user's first verified request in a process, legacy users (`auth_provider IS NULL`) with the same verified email are re-keyed to the Firebase uid in one transaction. This covers every table with `user_id` (found through `information_schema`) plus `edge_heat.contributor_ids`. Rows that would break a unique constraint (consent, a duplicate vote or connector) are dropped as duplicates, and the result is logged. `scripts/migrate_user_ids.py` has `--list`, `--email … --dry-run`, `--to-uid`, `--from <uid>` and `--purge-fake [--dry-run]`.
- Frontend: `firebase@12.19.0` (released 2026-09-09) pinned exactly. `services/firebase.ts`; `services/auth.ts` (`signInWithGoogle` uses a popup, falling back to a redirect when the popup is blocked or in an iOS standalone PWA; `sendEmailLink` has a 60 s client cooldown; `completeEmailLinkSignIn` cleans the URL with `history.replaceState`; `onAuthStateChanged` feeds a `useAuth()` store; `getIdToken`; `signOut`). `api.ts` has one `authedFetch` that adds the bearer token and retries once with a refreshed token on a 401. Every `X-User-Id` and `userId` parameter is gone. New `SignInCard` ("Continue with Google" plus "Email me a sign-in link", then "Check your inbox…"), `EmailLinkFinish` (asks for the email when the link opens on another device), and `GET /auth/finish` serving the SPA. `DevToolsPage` is now an admin page gated by `/api/auth/me.is_admin`; the dev-key form, the "enter any email" forms and the GIS script are deleted. Saved routes no longer fall back to localStorage and report "saved" when nothing was saved.
- Vite reads `VITE_FIREBASE_*` from the repo-root `.env` (`envDir: '..'`). Without that config the sign-in card says sign-in isn't set up, and anonymous routing still works.

Tests:
- New `tests/conftest.py`. With `LOAM_ENV=test`, an autouse fixture overrides the auth dependencies so a test acts as a user through the test-only header `X-Test-User` (plus `X-Test-Admin`). Nothing in `app/` reads it. The `real_auth` fixture removes the overrides.
- New `tests/test_round7_auth.py` (21 tests). Google's certs are monkeypatched to a locally generated RSA key, so signatures are really checked, offline. A forged signature, a non-JWT bearer, `X-User-Id` alone and an expired token each give 401 on `/api/saved-routes`, `/api/privacy/export` and `DELETE /api/privacy/account`. A wrong `aud`/`iss` and an unverified email-link user also give 401. `X-User-Id: jjrpfister@gmail.com` (with or without the old dev key) gets 401 on 4 admin endpoints, and 403 when combined with a valid non-admin token. Admin needs a verified, listed email. Production refuses the default connector key. The legacy re-key is covered, including the duplicate consent row. A source scan finds no header identity left in `app/` or `frontend/src/`.
- Deleted tests that asserted fabricated behaviour: `test_gh17_fixes.py::test_google_id_token_verification_valid` and `::test_google_id_token_verification_expired` (they accepted unsigned JWTs with `"mock_signature_bytes_for_test"`), `test_gh19_fixes.py::test_real_google_sso_authentication` (same), `test_round3_fixes.py::test_api_dev_status_google_sso_auth` (granted admin to `X-User-Id: jjrpfister@gmail.com`), and the `/api/auth/verify` steps in `test_stage2_mvp.py` and `test_e2e_acceptance.py` (they made up users from a JSON body). Rewritten to use the test fixture: saved-route CRUD, dev console access (anonymous 401, rider 403, admin 200), and the admin calls in the stage 4, 5 and 6 tests.
